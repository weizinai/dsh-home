# code-comments：代码注释约定

注释解释「为什么」和「约束」，代码负责「做什么」。本文件是语言无关的通用约定。写、改、审代码时「必须」级一律遵守，「建议」级在可行时遵守。

本规范管注释里写什么；空白、换行、缩进这类排版由 `.editorconfig` 与 `dotnet format` 管。

级别：**必须** = 违反即缺陷，评审必拦，且能一眼判定违反与否；**建议** = 可行时遵守，不阻塞提交。没有第三级；判不动「违反还是没违反」的写进下面的第一原则，不写成规则。

## 1. 第一原则

- **必须**：注释不复述代码。`i++; // i 加一` 是噪声，删掉。
- **必须**：优先让代码自解释。改命名、拆函数都比加注释划算；注释会随代码变更而过期，代码不会。
- **必须**：只在代码表达不了的地方写注释：意图、动机、约束、代价、坑。
- **必须**：注释不复述已有文档。架构、规则、机制有正本（如 `docs/architecture.md`）就在那里说；注释只带代码旁边的本地理由。

## 2. 该写的场合（以下都必须写）

- **必须**：公共 API 契约——参数含义、返回值、抛出行为、副作用、空值语义。
- **必须**：非显然的「为什么」——为何这样绕、为何用这个算法或阈值。
- **必须**：魔数的来源——无法具名时注明出处。
- **必须**：反直觉的 workaround——注明兼容的对象与版本。
- **必须**：并发与线程安全假设——谁在什么线程调用、是否可重入。
- **必须**：单位与量纲——签名体现不出时注明（毫秒、字节）。
- **必须**：危险操作——删数据、改全局状态、性能敏感路径。

## 3. 不该写的

- **必须**：不复述签名或流程（`// 遍历数组`）。
- **必须**：不留被注释掉的死代码。删掉，版本控制记得住。
- **必须**：不写修改记录与作者日期（`// 2024-03-01 张三 修改`），这属于版本控制的职责。文件头只允许 license 头与生成标记。

## 4. 文档注释与实现注释

- **必须**：文档注释（JSDoc / TSDoc / XML / docstring / JavaDoc）只写代码用户该读的内容；实现注释写维护者该知道的「为什么」。
- **必须**：文档注释写契约：调用者必须知道的参数含义、边界、副作用、抛出行为。首句写签名没表达的信息，禁止只复述参数名和类型。
- **必须**：签名表达完整时仍要写行为契约。丢弃、空值、门禁、线协议这类语义必须落在文档注释里。
- **必须**：`public` / `protected` 成员必须有文档注释。签名已完全表达语义的成员（同构转发、纯属性、常量）可不写；但仓库若用 CS1591 拦截缺失的 `<summary>`，以编译器为准，这时纯属性也要写。`internal` / `private` 成员在非显然时必须写注释。非显然 = 有边界（什么输入不行）、有副作用（除返回值外还动了什么）、或绕得需要解释。

## 5. 格式

- **必须**：注释放在被注释对象之前。
- **必须**：写完整句子，结尾带标点；注释用中文，仓库 `AGENTS.md` 另有规定时从其规定。英文注释首字母大写。
- **必须**：同一文件内注释语言一致。
- **必须**：实现注释多行时用多条行注释（`//`），不用块注释穿插在逻辑中间。
- **必须**：`TODO` / `FIXME` / `HACK` 不裸写：写就必须给出移除条件（`// TODO: SMAPI 4.0 发布后删掉这个兼容分支`）——不带移除条件的 TODO 等于永不做。可以带跟踪号，但只能是外部可解析的 URL；禁 `.scratch/` 编号。
- **必须**：注释不引用提交物里解析不了的标识：`NN 裁决`、`NN 票`、`spec NN`、`issue NN`、裸 `（NN）` 指向的编号在 git 里不存在。
- **必须**：注释不承担分区职责。不用 `// 初始化`、`// 农场域` 这类标签给代码分段；语言有 `#region`/`#pragma region` 这类结构化折叠指令时，只用于平坦数据表与配置分组，不给方法体分段。说明「为什么可以忽略」的注释（`// 正常取消`）不属于分区标签。
- **建议**：不用装饰性分隔线，仅在超长文件里辅助导航时用。
- **建议**：行尾注释仅在极短标注时用。

## 6. 语言特有规则

以下条目在各语言里的记法不同，按该语言的习惯与工具选择写法。

- **必须**：文档注释的标签（`<param>` / `<returns>` 等）仅在增加信息时写。
- **必须**：弃用标记（C# `[Obsolete]` 等）带替代方案或修复指引。
- **建议**：重写或接口实现优先用该语言的继承机制（如 C# `<inheritdoc/>`），不复制父级文档。
- **建议**：调用点参数含义不清时用参数名注释：`/* shouldRender= */ true`。

C# 的记法与补充规则见 [references/csharp.md](references/csharp.md)。

## 写完自查

逐条过一遍：注释里没有复述代码的句子；每个公开契约的丢弃、空值、抛出都已写明；`TODO` 都带移除条件或外部跟踪 URL；弃用标记都带替代方案。
