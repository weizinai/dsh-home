# 沉淀一次会话的知识

把一个模组任务闭环里新学到的**通用**知识收进 `stardew-modding` 技能。技能本体在本仓库的 `.dsh/skills/stardew-modding/`（`SKILL.md` + `references/` 下每个领域一份小写 md）。六步走完才算一次沉淀。

## 1. 圈定范围

本会话完成了哪个模组任务闭环：动了哪些文件、撞了哪些坑、查过哪些来源。

**判据**：三样都能逐条说出来，每样指得出具体文件、命令或来源。

## 2. 提候选

每条候选填满四格：

| 格 | 内容 |
|---|---|
| 结论 | 一句话，写成结论式标题，不是"关于 X 的说明" |
| 弯路 | 下次遇到同类问题，它能让我少走哪条弯路——填不出来就不提这条 |
| 依据 | 这条事实我在哪个来源里核实过（写在你给我的说明里，不进文件） |
| 落点 | 并入哪个文件的哪一条，还是新起一条 |

清单里必须有**删除或合并**这一类：扫一遍既有条目，指出被新事实取代的、重复的、过期的。只提新增，技能就是在单调膨胀。

**判据**：每条候选四格齐全；清单末尾对既有条目给出删除/合并结论（结论可以是"没有"）。

## 3. 逐条裁决

把清单交给用户，等他对每条给出：收 / 拒 / 收但改口径。

**判据**：每条候选都有裁决，没有悬空的。

## 4. 就地修订

通过的候选写进文件：默认**并入**既有条目，与既有内容完全正交才新起一条；写完把被取代的旧表述删掉。每条事实写之前都在源码或在线文档里核实过，没核实过的标"待查证"。文件里只留结论，不写出处。

**判据**：每条通过的候选都能指出它落在文件哪一行；被取代的旧表述零残留。

## 5. 排他检查

正文只写与具体框架无关的通用事实。当前仓库若有 PiCore 这类自建框架，允许的唯一提及是那句"有则优先复用"的指路。

**判据**：逐条问「换一个模组、换一个作者仍然成立吗」——不成立的就是某模组的机制，归它的 `docs/architecture.md`，不进技能。正文里除那句指路外，搜不到任何框架专属标识符。

## 6. 冷启动盲测

派一个**子代理**（新上下文），给它一类正好压在本次新增内容上的问题，不告诉它技能存在，让它交出答案并自报加载了哪些技能。

**判据**：子代理答对，且答案是照技能里的结论给的。不过关就改**写法**——先看 `description` 的触发措辞，再看那条知识有没有写成结论式、有没有被出处和铺陈淹没。加内容不会让它更容易被照做。

## 收尾：回报

技能可以被就地改写，但改完不报告，等于替用户做了他没批准的修改。结束时在回复里说明：改了或新增了哪几条、依据是什么、盲测结果如何。

## 新领域怎么落

新起一个 `.dsh/skills/stardew-modding/references/` 下的小写 `.md`（如 `references/scaffold.md`），在 `SKILL.md` 的"遇到这类问题"两列表里加一行。只有新增领域改变了技能的触发范围时，才动 `SKILL.md` 的 `description`——它每个会话都在花上下文，目录条目上限 500 字符。
