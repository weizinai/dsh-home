所有提交消息（包括普通提交与 squash）默认使用 Conventional Commits，消息用中文；仓库约定或当前任务另有要求时从其约定。

## 范围与授权

本技能授权执行 `git commit` 及为提交而做的暂存，覆盖普通提交与 squash 产生的提交。改写已有提交（`git commit --amend`、`git rebase`）与推送不在授权内，需要时另行确认。

提交范围按当前任务授权确定：只提交本次授权范围内的改动，保留无关改动；密钥、凭据和私钥不进入提交。待提交内容与任务授权不符时先问用户，不自行扩大范围。

## 提交流程

1. 查 `git status --porcelain`、`git diff` 和 `git diff --staged`，确认待提交范围、已有暂存内容与必要验证结果。
2. 按一个逻辑变更选择文件或片段暂存；密钥、凭据和私钥不进入提交，保留无关改动。
3. 依据最终暂存 diff 写消息，按下面的「消息格式与类型」。单行可用 `git commit -m`；多行先写临时文件，再用 `git commit -F <文件>`，完成后删除该临时文件。
4. 核对提交内容与消息、剩余工作区状态，确认只提交了本次授权范围。

## 消息格式与类型

第 3 步写消息时按下列格式与类型。

```text
<type>[可选 scope][可选 !]: 中文描述

- [可选正文要点]

[可选脚注]
```

`type`、`scope` 和协议标记用英文；描述、正文及脚注说明用中文，保留代码标识符、链接和 issue 编号。

| type | 用途 |
| --- | --- |
| `feat` | 新功能 |
| `fix` | 修复缺陷 |
| `docs` | 仅文档 |
| `style` | 格式或风格，无逻辑变化 |
| `refactor` | 重构，无新功能或缺陷修复 |
| `perf` | 性能改进 |
| `test` | 新增或更新测试 |
| `build` | 构建系统或依赖 |
| `ci` | CI 或其配置 |
| `chore` | 维护杂项 |
| `revert` | 回滚提交 |

`scope` 用仓库已有的模块词汇；范围不清或没有约定时省略。描述直接说明改动，一般控制在 50 字以内。正文可省略；需要时统一使用 `- ` 分点格式，每点交代一项动机、行为差异或影响，不必重复 diff。标题、正文与脚注之间留空行。正文每行不超过 72 个字符（含分点标记和缩进）；长分点在语义边界换行，续行缩进两个空格。

破坏性变更用 `!`（如 `feat!: 移除已废弃接口`）或 `BREAKING CHANGE: 中文说明` 标明。
